POPO-OPD-Relay 从备题到出图的全过程

本质上是，先把题库切成训练题和测试题两个文件（里面 3 个数字和 4 个数字的题混在一起，读的时候只留 3 个数字的），用训练题把 1.5B 模型训成教师，再让教师逐个 token 带 0.5B 学生；每个训练出的模型都拿同一份 1,477 道测试题去答，答对数最后汇总成表和图。

GRPOTrainer 一步训练里发生了什么：GRPO 正式运行的第 2 步

本质上是，每一步拿 4 道题，让模型给每道题写 8 个回答并打分，同一道题里比平均分高的回答被往"更可能写出来"推、比平均分低的被往回拉，攒满 16 次再改一次模型。

POPOTrainer 和 OPDTrainer 是怎么接到 TRL 的 GRPOTrainer 上的

本质上是，TRL 每一步都按名字去叫 _generate_and_score_completions（让模型写回答、打分），POPOTrainer 把 POPO 写的同名方法排在 TRL 前面，所以先被叫到的是 POPO 的；POPO 再把活交回给 TRL 做完，拿回结果换掉死组。

POPO 的死组重放：正式运行里第 1–3 步走的全过程

本质上是，一道题的 8 个回答得分全一样（死组）就学不到东西，于是把它换成缓冲区里最近一道有对有错的旧题和当时的 8 个回答，再按现在的模型给这些旧回答重新打分，算出权重 ρ 乘上去。

POPO-OPD-Relay：交给模型的是什么，模型输出的是什么

本质上是，模型每次拿到的都是同一段题目文字，只换里面的三个数字和目标数，模型接着这段文字往下写出解题过程和 <answer> 里的算式；到了 POPO 重新打分和 OPD 教师打分的时候，模型不再写字，而是给一份已经写好的回答里的每个 token 各打一个分（logp）。

依据：仓库 Solomenn/POPO-OPD-Relay 最新提交 06ed502 的源码，以及 results/raw/ 里的评测文件。

一、项目里有五个地方把东西交给模型（按运行先后）

第 1–4 处发生在训练的每一步里（每一步 4 道题 × 每题 8 份回答 = 32 行）；第 5 处是训练结束后由用户另行运行的评测。

1训练时模型写回答（GRPO、POPO、OPD 三种训练都有）TRL 的 GRPOTrainer 用 vLLM 调用正在训练的模型
交给模型一道题的题目文字 prompt（由 src/countdown.py 的 format_prompt 把 nums 和 target 填进模板 PROMPT 得到），同一道题交 8 次。
→
模型输出8 份不同的回答文字 completion：模型从题目最后的 <think> 后面接着写，写到 </answer> 或 "\nUser:" 停下，最多写 1024 个 token。温度 1.0，所以 8 份各不相同。
→
输出交给谁reward_countdown 用 is_correct 给每份回答判分：答对 1.0，答错 0.0。TRL 再用同一道题 8 个分数算出每份回答的优势。
2训练时模型给回答打 logp（三种训练都有）TRL 的 GRPOTrainer 调用正在训练的模型
交给模型题目的 token（prompt_ids）和回答的 token（completion_ids）接成的一整行。
→
模型输出回答里每个 token 的 logp：模型在这个位置写出这个 token 的概率取对数，一个 token 一个数。
→
输出交给谁TRL 把这些 logp 存成 old_per_token_logps；算损失时 TRL 让模型给同样的回答再算一次 logp，两次相除得到比率，比率乘优势得到损失，再更新模型。
3POPO：现在的模型给缓冲区里的旧回答重新打分src/POPO.py 的 _logps_no_grad，只在 python train.py --popo 时发生
交给模型缓冲区里一道旧题的题目 token 和当时的 8 份旧回答 token（只在这一步出现 8 份回答得分全一样的题时才发生）。
→
模型输出旧回答里每个 token 的 logp（现在的模型给的分）。模型不写新字。
→
输出交给谁decoupled_is_weights 用它和旧回答采样时的 logp 算出每个 token 的权重 ρ。
4OPD：教师模型给学生写的回答打分src/OPD.py 的 teacher_logps_no_grad，只在 python train.py --opd 时发生
交给教师模型学生在第 1 处写出的 32 份回答，每份连同它的题目 token 接成一行，每次交 8 行（opd_teacher_batch_size = 8）。
→
教师模型输出学生回答里每个 token 的 logp（教师给的分）。教师不写新字。
→
输出交给谁opd_token_weights 和 apply_opd_token_advantages 用 教师 logp − 学生 logp 算出每个 token 的优势，替换 TRL 原来的优势。
5评测时模型写回答evaluate_countdown.py 的 main，用 vLLM 调用被评测的模型
交给模型1,477 道测试题的题目文字（同一个 format_prompt 模板），每道题交 1 次。
→
模型输出每道题 1 份回答文字。温度 0（每一步都选概率最大的 token），最多 512 个 token，停止条件和训练时一样。
→
输出交给谁is_correct 判对错；evaluate_countdown.py 把每题的 idx、ok、equation、nums、target、completion 写成 JSONL 的一行。

三、回答文字怎么变成分数（src/countdown.py 的 is_correct）

  1. extract_equation 在回答里找 <answer>，取它后面到 </answer> 为止的文字；没有 </answer> 就取到回答结尾；没有 <answer> 返回 None。例：" … <answer> (84 + 48) - 36 " → "(84 + 48) - 36"。
  2. evaluate_equation 检查算式只含数字、+ − * /、括号和空白，再算出它的值，同时记下用到的整数。例："(84 + 48) - 36" → 值 96，用到 [84, 48, 36]。
  3. is_correct 比较两件事：用到的整数和题目的 nums 完全一样（每个恰好一次），而且值恰好等于 target。两件都成立返回 True，否则返回 False。
  4. 训练时 reward_countdown 把 True 记成 1.0、False 记成 0.0；评测时 evaluate_countdown.py 把 True/False 写进 ok 字段，并累加答对数。

四、模型给回答打分时，交进去和拿出来的样子（第 2、3、4 处）

代码把题目 token 和回答 token 接成一行交给模型；模型对每个位置给出下一个 token 的概率，代码只取回答那一段、只取回答里实际写出的那个 token 的 logp。下面用第二部分 POPO 教师回答的开头示意（token 的切法只为示意，实际以分词器为准）：

…stepbystep.\n<think> 84logp+logp36logp</think>logp=logp120logp……
题目 token：交给模型，不取分回答 token：交给模型，每个取一个 logp
位置哪个模型打分打分对象拿到 logp 之后算什么
第 2 处正在训练的模型本步刚写出的 32 份回答TRL 用 logp 和优势算损失。
第 3 处 POPO现在的模型（正在训练的 Qwen2.5-1.5B）缓冲区里旧题的 8 份旧回答ρ = exp(现在的 logp − 采样时的 logp)
正式运行 rho_clip = 2.0，超过 2.0 的 ρ 压到 2.0；代码把 ρ 写进 importance_sampling_ratio，TRL 把它乘在这些旧回答的损失外面。
第 4 处 OPD教师：配对 POPO 教师第 400 步（manifest 里 opd_teacher_model 指向 popo_s42），或独立重训的 GRPO 教师第 400 步学生本步写出的 32 份回答优势 = 教师 logp − 学生 logp
正式运行 opd_weight_clip = 3，差值裁到 −3 到 3 之间。教师比学生更愿意写的 token 优势为正，学生被推向更常写它。

OPDTrainer 一步训练里发生了什么：学生正式运行的第 1 步

本质上是，学生自己写 32 个回答，教师给回答里的每个 token 再打一次分，用教师的分减学生的分当这个 token 的优势：教师比学生更愿意写的 token 被往“更可能写出来”推，教师比学生更不愿意写的被往回拉。

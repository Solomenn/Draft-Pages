Transformer 整体：编码器读原文，解码器一轮写一个 token

本质上是，编码器把整句原文读一遍，给每个 token 写成一行带着上下文的数；解码器每一轮拿已经写出的译文去读这些数，写出下一个 token，直到写出结束符。

注意力怎么算：编码器第 1 层的多头自注意力

本质上是，每个 token 拿自己的 Q 去和每个 token 的 K 比一比，比出来的分数变成加起来等于 1 的权重，再按这些权重把所有 token 的 V 加在一起，当作自己的新向量。

编码器一层里发生了什么：原文“我 爱 猫”

本质上是，3 个 token 的向量先互相看一遍、再各自加工一遍，每次都把加工前的向量加回来，出来还是 3 行、每行一样长。

解码器一层里发生了什么：第 3 轮，输入 <bos> I love

本质上是，译文里每个 token 先只看自己和前面的 token，再去原文的编码器输出里取信息，然后各自加工一遍；最后一行用来猜下一个 token。

从编码器 + 解码器模型推出单纯解码器模型

本质上是，把原文接到译文前面放进同一行，love 这一行用一个掩码多头自注意力就能同时从原文和译文取信息，于是多头交叉注意力和编码器都可以删掉，剩下的就是单纯解码器模型。

训练和推理：为什么只有推理需要 KV Cache

本质上是，训练时整句话“我 爱 北 京”事先全都知道，一次算完所有位置的 K、V，这次算完就结束了，没有下一步再用它们；推理时下一个 token 要等上一个生成出来才知道，每步都要看前面所有 token 的 K、V，所以把算过的 K、V 存进 KV Cache，下一步直接取。

这一步新算的 从 KV Cache 取的 没有 KV Cache 时要重新算的 被因果掩码挡住，不看 还不知道
